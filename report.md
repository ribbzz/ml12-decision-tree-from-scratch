# Binary decision tree from scratch

**GitHub:** https://github.com/ribbzz/ml12-decision-tree-from-scratch  
**Course:** ML1.2  
**Scope:** binary classification on tabular data.

## Objective and implementation

The decision tree uses entropy and information gain to choose splits. Split search, tree growth, prediction and display are written in Python using the standard library.

The classifier accepts numeric and categorical predictors with two target classes. Labels can be strings or other hashable values. A one-class training sample produces a constant classifier; three or more classes raise an explicit error. “Any dataset” means a compatible binary tabular dataset, not arbitrary images, free text, regression targets or multiclass targets.

`src/scratch_tree/tree.py` contains the implementation. `cli.py` reads a generic CSV and runs a reproducible evaluation. The included teaching data are generated by `examples/generate_data.py`; they are artificial, not real student records or a benchmark collected from people.

## Entropy and information gain

For a binary sample with proportions p and 1−p, entropy in bits is:

$$H(S)=-p\log_2 p-(1-p)\log_2(1-p).$$

A zero-probability term contributes zero. Pure and empty samples have entropy zero. An equally divided sample has entropy one.

For candidate left and right children:

$$IG=H(S)-\frac{|S_L|}{|S|}H(S_L)-\frac{|S_R|}{|S|}H(S_R).$$

For example, the labels `[no, no, yes, yes]` have entropy 1. Splitting hours `[1, 2, 6, 8]` at 4 gives two pure children. Their weighted entropy is 0, so the information gain is 1. The executable `examples/demo.py` reproduces this calculation and displays the resulting tree.

## How the tree is learned

1. Validate the shape, feature types and binary labels. Encode class counts using the order labels first appear.
2. At each candidate leaf, calculate its entropy.
3. For a numeric column, sort observed values and examine boundaries between distinct adjacent values. Class counts are updated incrementally during the scan.
4. For a categorical column, examine questions of the form `feature == category`; all other observed categories take the opposite branch.
5. For missing values, evaluate assigning them to each child. Also consider a missing-versus-observed split. Keep the direction that improves the objective most while respecting minimum child sizes.
6. Retain the best positive-gain split. When a leaf budget is active, grow the available split with the greatest sample-weighted entropy reduction first.
7. Stop at a pure node, an exhausted depth/leaf budget, insufficient samples, or no sufficiently positive information gain.

A leaf predicts its most frequent class. A tie uses the class encountered first in training. `predict_proba` returns class proportions in the reached leaf; these are not calibrated confidence guarantees. Split ties are deterministic in feature/candidate order. Previously unseen categorical values follow the “not equal” branch of an equality question.

Numeric split scanning costs sorting plus a scan per feature at each node. Categorical class counts are accumulated per category. This pure-Python implementation is intended for teaching and moderate datasets; it does not promise the throughput of optimized production libraries.

## Tree-size hyperparameters

| Parameter | Default | Meaning |
|---|---:|---|
| `max_depth` | 5 | Maximum root-to-leaf edges; root depth is 0. |
| `max_leaf_nodes` | None | Hard maximum on terminal nodes. |
| `min_samples_split` | 2 | Minimum samples needed to attempt a split. |
| `min_samples_leaf` | 1 | Minimum samples required in each resulting child. |
| `min_gain` | 1e-12 | Required local information-gain improvement. |

The CLI exposes `--max-depth`, `--max-leaves` and `--min-leaf`. Increasing allowed tree size can fit more detail, including noise. These controls are pre-pruning; no post-pruning is implemented.

## Reproducible experiment

The artificial dataset has 1,000 examples, three mixed-type predictors, two labels, approximately 4% deliberately flipped labels and approximately 3% missing numeric features. A fixed seed generates it. A separate fixed seed creates an 800-row training / 200-row stratified validation split. Feature-type inference uses training rows only. The target and explicitly dropped columns are excluded from predictors.

Commands:

```bash
uv sync
uv run python examples/generate_data.py
uv run python examples/evaluate.py
uv run scratch-tree --csv examples/practice.csv --target passed --max-depth 4 --max-leaves 12
```

Measured results from `examples/depth_results.json`:

| Maximum depth | Leaves | Training accuracy | Validation accuracy | Validation balanced accuracy |
|---:|---:|---:|---:|---:|
| 0 | 1 | 63.25% | 63.50% | 50.00% |
| 1 | 2 | 80.13% | 81.00% | 84.46% |
| 2 | 4 | 83.25% | 84.50% | 79.64% |
| 3 | 7 | 90.75% | 91.00% | 91.75% |
| 4 | 12 | 90.88% | 90.00% | 90.38% |
| 6 | 31 | 94.50% | 94.00% | 92.95% |
| 10 | 72 | 96.88% | 90.00% | 88.05% |

Depth 10 fits the training examples more closely than depth 6 but performs worse on validation. The larger tree starts fitting noise in the training data. These depths were compared on the same validation set: the best score is a selection result, not an unbiased final-test estimate. Results on synthetic data do not establish performance on real datasets.

Balanced accuracy is the mean recall of the classes represented in the evaluation split. Per-class support and recall are printed explicitly. Singleton classes are kept in training; when a class has no evaluation examples, its recall is reported as undefined rather than invented.

Run `uv run python -m unittest discover -s tests -v`.

They cover hand-calculated entropy and information gain, a brute-force check of split quality, numeric/categorical features, binary probabilities, missing routing, unseen values, extreme floating-point boundaries, pure/constant datasets, size limits, deterministic behavior, refitting, text/DOT output, CSV evaluation, invalid inputs and explicit multiclass rejection. ## Tree display bonus

The CLI prints split conditions, gain, entropy, sample counts, class counts and leaf predictions. Text output needs no extra software.

```bash
mkdir -p outputs
uv run scratch-tree --csv examples/practice.csv --target passed --max-depth 3 --dot outputs/tree.dot
# Optional: install Graphviz separately to render the exported DOT file.
dot -Tsvg outputs/tree.dot -o outputs/tree.svg
```

DOT export is available. Graphviz is not installed in the current environment, so local verification covers the exported graph source and text display, not Graphviz rendering.

## Limitations

The estimator supports binary targets only. Categorical splits test one category against the rest, not every possible subset. Greedy positive-gain growth can fail on interactions such as XOR that require an initially zero-gain split. There is no sample weighting, post-pruning, probability calibration, model persistence format or parallel training. Random stratified evaluation assumes independent rows; grouped or chronological data need an appropriate split instead. Numeric features use floating-point representation.
